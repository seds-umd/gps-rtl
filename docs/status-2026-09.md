# GPS receiver status, September 2026

Where the custom GPS receiver stands after the September 2026 audit of this
repository, `gps-model` and `fpga-utils`. Written for whoever picks the project
up next; the team plan in Drive has the wider context.

## What exists, by evidence

| Piece | Where | State |
| --- | --- | --- |
| RF front end | `max2769-dev-board` (KiCad, 2023) | Built; plugs into a Digilent board over PMOD. |
| Bench capture path | `hw/integration/uart_top`, `scripts/basys_max.py`, `scripts/gps_tx.py` | Demonstrated April 2025: simulated GPS from a PlutoSDR through 60 dB of attenuation into the dev board on an Arty A7-100, samples over UART, software acquisition at about 13 dB SNR. |
| Acquisition gateware | `AcquisitionModular` and its modules; `hw/integration/eth_top` | Detected 7 of 10 simulated satellites on the Kintex-7 board in 2024. Nine seeded acquisition cases now pass in simulation with the vendor FFT model. |
| Core top level | `GpsTop` | Board-neutral serial-to-acquisition core with a result stream and overflow flag; acquires a simulated satellite end to end in simulation. No board wrapper, host transport, tracking or navigation. See `acquisition-core.md`. |
| Python reference model | `gps-model` | Acquisition and single-satellite tracking work; navigation decoding is partial; no position solution. |
| Flight board | `gps-v1` (KiCad, last edited February 2025) | Six-layer 50 x 50 mm design around an XC7S15. No record of fabrication. |
| OBC side | `obc-firmware` SPI1, pull request #9 | The FPGA loader PR is a prototype: never called from main, placeholder bitstream size, inverted timeout. Do not merge as is. |

Not demonstrated anywhere: a live-sky acquisition with the team's own code,
gateware tracking, a navigation solution, or a bitstream from the current tree.

## What the audit changed

- Regression restored: every testbench runs from the root `make`, and a strict
  result checker fails the run on missing, empty, skipped-only or failed
  results. Before, 2 of 20 directories ran.
- Tests that had no assertions now assert: MAX2769 samples and timestamps, SPI
  startup words, the FFT tone, seeded acquisition cases.
- Bugs fixed: the acquisition phase origin was subtracted in the wrong domain;
  fine-acquisition frequency labels in the Python model were off by one bin
  spacing; the UDP host tool dropped the last-fragment flag on exact-size
  payloads and had no read timeout.
- `GpsTop` wired and tested; the Ethernet bench runs without vendor primitives;
  a sticky FIFO overflow flag was added.
- Companion changes: `fpga-utils` loads the Linux-only FFT model lazily, packs
  I/Q as unsigned words and accepts explicit test module names; `gps-model`
  gained reference tests.

## How to run

See the README section "Run the regression". Native subset on a Mac:

```bash
SKIP_TESTS="AcquisitionModular FFT-xilinx EthernetTestbench GpsTop" make
```

The four skipped directories need a Linux x86_64 environment; the README gives
a Docker recipe.

   Kintex board, any gps-v1 boards, the GPS antenna.
2. Repeat the April 2025 dev-board test with this tree, then a live-sky capture.

   sample phase, fewer satellites than the Python model).

   and qualify it at the real clock ratio.
5. Tracking, keeping the design split: correlators and decimation in hardware,
   loop filters in software.
